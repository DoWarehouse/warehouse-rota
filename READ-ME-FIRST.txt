# Weekly shifts inside the shift window — 14 November 2026

This is an interface-only update for your existing Dylan Oaks warehouse rota. It adds a read-only summary of a colleague’s saved shifts while adding or editing a shift. No server file, database, saved staff information or settings file is included in the update ZIP. There is no database migration.

## What you will see

Open an empty cell or an existing shift. **Shifts this week** shows:

- All seven days of the week containing the date in the shift window.
- Each saved shift’s times, department, WH1/WH2, labels and training/absence type.
- Split shifts, next-day finishes, and assignments at other locations.
- Saved weekly hours after unpaid breaks, with no-show hours excluded as in the main rota.
- An **Editing** marker on the existing shift when editing it.

The summary updates when you choose another colleague or date. It includes all their assignments, even when the main rota is filtered. Scroll within the summary to see later days. You can collapse it by clicking its heading. On a wide screen it sits alongside the form; on a phone or tablet it appears above the shift fields.

The summary contains saved shifts only. A shift you are adding, or edits you have not saved, appear after you save them. Changing the summary does not reset your unsaved times, label or note. **Refresh summary** reads the latest saved week without saving the form. A failed read can be retried.

For bulk assignment, select one colleague to see their weekly summary. With several colleagues selected, the panel asks you to select one for the individual reference; this does not change the existing bulk-assignment behaviour.

## Preserve your existing information

The update ZIP contains only these three application files, plus these instructions:

```text
warehouse-rota/public/app.js
warehouse-rota/public/styles.css
warehouse-rota/public/index.html
```

Your existing server, database, colleague profiles, availability, shifts, holiday balances, attendance, required hours, templates, dashboard connection, publications and QR links remain in place. No new demo data is installed. The normal existing Save, Remove shift, Delete colleague and Clear controls retain their existing behaviour; this summary does not call them automatically.

Before deployment, use **Settings → Download data backup** to keep your own current backup. Keep the existing Render persistent disk, DATA_DIR, environment variables and Root Directory **warehouse-rota/**.

## Upload this update

1. Extract **rota-shift-week-update.zip**.
2. Open the Code home page of **DoWarehouse/warehouse-rota**, branch **main**.
3. Choose **Add file → Upload files** and drag the inner **warehouse-rota** folder from the extracted ZIP into the upload area.
4. Confirm that the three application paths match the list above. Commit the three replacements together. Do not delete or reset any existing folder or file.
5. In Render’s **dylan-oaks-warehouse-rota** service, select **Manual Deploy → Deploy latest commit** and wait for **Live**. Auto-Deploy was off when this update was prepared.
6. Reload the rota, open an empty shift cell and look for **Shifts this week**. The page’s interface marker is **rota-shift-week-preview-20261114**. The server build value in Settings remains the existing one because the server is unchanged.

This package updates the screens; it does not deploy itself. The underlying server and schema files are byte-identical to the current saved version, whose three original interface files were confirmed to match the live service before editing.
